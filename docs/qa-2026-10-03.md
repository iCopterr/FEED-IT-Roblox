# Full game QA — 2026-10-03

## Result and scope

All **26 executed live Studio suites passed on their final runs**, plus the
targeted local/Studio regressions below. This is broad automated regression
coverage, not proof that every possible device, production service, or input
sequence works.

Baseline: commit `8d6395c`, with the owner's unrelated untracked artwork left
untouched. No production gameplay code, authored UI, economy values, saves,
entitlements, or published place were changed during this QA session. Changes
are test-fixture/expectation maintenance and an opt-in HUD smoke test.

Studio multiplayer tests used isolated memory-backed profiles
(`UseDataStoreInStudio=false`). Commerce tests used detached profiles and mocked
payment/persistence services. No real Robux checkout was completed.

### What the live tests cover

- Fresh startup/tutorial; initial balance $2,000; plot assignment, capacity,
  placement ownership/range, carry, income, inventory and wandering.
- Conveyor affordability, duplicate/racing requests, six egg tiers, incubation,
  hatch result timing, pet identity, and memory-backed save/load.
- Feed success/failure/critical transactions, food use, broken-pet retention,
  repair, VFX stages, index unlocks, prompts and labels.
- All 36 pet templates: roster/rig/scale checks and animation regressions.
- Client HUD replication, money text, launcher availability/single UIScale,
  menu visibility reopen cycles, volume groups and configured sound IDs.
- Boost visibility matches replicated eligibility. A separate local-only
  attribute probe confirms eligible rendering within HUD bounds and immediate
  hiding when restricted, then restores both attributes. It does not grant the
  pass or prove the owner's account has an active eligible entitlement.

The HUD smoke test toggles panel Visible properties; it does not simulate
physical taps on every launcher. Its log check ignores plugin-tagged entries.
RigEdit plugin notices were observed and are not treated as game failures.

## Test maintenance

Initial failures exposed old test assumptions from earlier designs. Updated:
- REVIVE SHARDS → REPAIR SHARDS copy.
- Unconfigured shop IDs/blank art/square shop expectations → current assets.
- Mobile right margin → -24 within safe area, matching the existing fix.
- Build dynamic repair-tab fixtures before responsive layout verification.
- Old stock fraction → numeric X-count; this checks the count, not exact casing
  or the presence of the word “stock”.
- Hidden legacy HatchUI may exist; it must not display during world hatching.
- Opening Index now closes remote panels.
- Broken pets remain in inventory rather than an old PendingRecovery slot.
- Inventory is a TextButton with a texture child, not an ImageButton.
- Conveyor affordability uses configured egg price, not historical $5,000.
- Egg label/prompt fixtures provide required Normal variant metadata.
- Index assertion label clarifies that synchronous hatch completion includes
  reward collection; index behavior itself was not changed.

Every affected live suite was rerun successfully. No reproduced production
gameplay defect was fixed or hidden by changing production code in this session.

## Remaining release checks — NOT verified here

1. **Physical mobile device:** latest HUD on the owner's actual phone, notch/
   orientation/safe insets, real touch targets, joystick/jump clearance and FPS.
   Automated geometry checks do not close the screenshot-reported visual issue.
2. **Published persistence:** real DataStore reconnect, cross-server session
   contention, shutdown/retry and outage recovery. Memory-backed roundtrips and
   mocked failures passed but are not a production DataStore soak.
3. **Real marketplace:** purchase dialogs, regional pricing/permissions,
   successful/cancelled actual receipts and a genuinely pass-owning account.
   No Robux spent; simulated receipt safety passed.
4. **Owner's x2 badge report:** synthetic eligible rendering passed, but actual
   owned-pass/policy state and visibility on the reporting account still need
   confirmation. Do not mark that account-specific issue resolved.
5. **Actual asset/audio delivery:** published permissions and subjective sound/
   animation quality on devices; long-session/full-server performance and
   network-loss/latency behavior.
6. **Human gameplay pass:** all buttons via mouse/touch/gamepad, menu scrolling,
   subjective readability and feed tension/fun.

## Repeating the HUD smoke test

In Studio edit mode with Rojo synced and memory persistence configured:

```lua
game:GetService("StudioTestService"):ExecuteMultiplayerTestAsync(2, "HUDSmokeVerification")
```

The server script is Studio/test-argument gated and refuses a non-memory adapter.
The client activates only when the dedicated test report remote exists.
